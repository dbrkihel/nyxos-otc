# nyxos-otc

An OTClient-based Tibia client running **protocol 15.25**, with a Cip-style
interface.

Maintained by **BRKiHeL**.

> **No game assets are included.** Sprites, appearances and sounds belong to
> CipSoft GmbH. You supply your own from a client you already have — see
> [Assets](#assets) below.

📖 **[Full documentation](https://dbrkihel.github.io/nyxos-otc/)** — step-by-step
build guides for Windows and Linux, setup, and the server-side changes some
features need. Also readable directly in [`docs/`](docs/).

**Prebuilt binaries:** every push to `main` produces Windows and Linux builds
under [Actions](https://github.com/dbrkihel/nyxos-otc/actions); tagged releases
attach them as archives. You still supply your own assets.

## What this client actually does

Everything listed here is implemented and wired to a real backend. Options with
no working implementation are greyed out or hidden rather than left as dead
switches, so what you see in the menus is what the client can do.

### Audio

A complete audio subsystem, built against the official client's sound bank.

- **Sound bank extraction** — `tools/soundbank.py` walks the protobuf in
  `sounds-<hash>.dat` by hand (no `.proto` is shipped) and emits
  `data/sounds/soundbank.json`: 815 files, 576 effects, 90 ambiences, 23 music
  tracks and 7 object groups.
- **Combat and spells** — per-source volume groups (your own, other players,
  creatures) with separate attack/healing/support channels, mirroring the
  official Battle Sounds page.
- **UI sounds** — buttons, chat message arrival, private messages, NPC dialogue
  blips, VIP login/logout, quest tracker add/remove, party join/leave.
- **Music** — title theme on the login screen plus server-driven tracks.
- **Ambience** — zone beds with randomised one-shots, driven by the server.
- **Object sounds** — fountains, torches and similar emit from their tile.
- **Positional audio** — ambient and object sources are panned by direction and
  attenuated by distance, recomputed every 50 ms against your live position, so
  moving away fades smoothly instead of cutting out.
- **Output device selection** — pick your sound device in the options menu, with
  fallback to the previous device and then to auto-select if it disappears.

### Protocol

- **Opcode `0x85` corrected.** In the modern protocol this carries ambient and
  music sound, not distance missiles — those moved into the `0x83` effect loop.
  The old missile parser read 12 bytes against the sound packet's 3, so every
  packet after it in the same frame was misread. Symptom: creatures appearing to
  teleport several tiles. Fixing the routing fixed the desync.
- **Opcode `0x83` alignment** and a related 1-sqm walk rollback.
- **Extended opcode `0x1C`** exposed to Lua, which the NPC dialogue window uses.

### Interface

- **Cip-style NPC dialogue window** — portrait, caption banner, clickable
  `{keywords}`, your own speech echoed back, a docked trade column, and
  remembered position and size. Talking to an NPC uses a private channel rather
  than the general chat.
- **Options menu** — Sound, Battle Sounds, UI Sounds and Help pages; per-section
  reset; Auto-Insert New Spells; "ask before sorting / moving contents of nested
  containers".
- **Minimap persistence** — explored area is saved on logout, on client close
  and every 5 minutes, to `%APPDATA%/NyxosClient/Nyxos/minimap.otmm`, and read
  back on the next session.

### Engine and tooling

- CMake + Ninja build that bootstraps vcpkg on first run; a Visual Studio
  solution is kept in `vc17/` as a second path.
- Vendored ANGLE for a DirectX backend alongside OpenGL.
- Encrypted asset packaging: the master key is derived via HKDF-SHA256 from
  per-release material generated by `tools/gen_asset_key.py`, so the key bytes
  never appear contiguously in the binary. This is obfuscation, not a vault —
  the material has to live in the binary for the client to decrypt its own
  assets.
- Crash reporter with minidump symbolication.

## Building

Windows only, for now. Full detail lives in [BUILD.md](BUILD.md); the short
version:

```powershell
# Visual Studio 2022/2026 with "Desktop development with C++", plus git on PATH.
.\compile-cmake.ps1 -Config Release
```

Both build paths bootstrap vcpkg themselves — you do not need to install it.

## Configuration

```powershell
copy config.example.lua config.lua
```

`config.lua` is gitignored. Edit that copy, not the example. It holds your login
endpoint, optional auto-login credentials for UI iteration, and a few developer
switches (in-client terminal, `.otui` hot reload). Everything in it is optional:
the client falls back to `127.0.0.1` defaults from `init.lua`.

## Assets

None of the following ship with this repository. Copy them from a Tibia client
you already have:

| What | Where it goes |
|---|---|
| `appearances.dat` + sprite sheets + `catalog-content.json` | `data/things/1525/` |
| Sound bank audio (`sound-*.ogg`) | `data/sounds/` |

The sound **index** is tracked (`data/sounds/soundbank.json`); the audio is not.
To regenerate the index from your own client:

```bash
python tools/soundbank.py path/to/sounds-<hash>.dat data/sounds/soundbank.json
```

Without the `.ogg` files the client runs fine and simply plays nothing.

## Before you run your own server

Two values ship as deliberate placeholders and must be changed:

1. **`HWID_SECRET`** in `src/client/protocolgameparse.cpp` — a shared secret
   with the server's anti-multibox handshake. A published value can be forged by
   anyone. Change it here *and* in `huntMonitorHwidSecret` on the server.
2. **Asset key material** in `src/framework/core/resourcemanager.cpp` — run
   `tools/gen_asset_key.py` so your build does not ship the same key as every
   other clone.

If your server sells anything, the store's terms-of-service text in
`mods/game_store/store.lua` is an empty placeholder and needs terms written for
your own operation and jurisdiction.
